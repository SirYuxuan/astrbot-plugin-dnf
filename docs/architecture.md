# 架构与扩展约定

## 目标

保留金币比例、油价和蛋价的查询及监控行为，把插件整理为可以继续添加基础功能的结构。
采用显式装配，不引入动态扫描、装饰器注册中心或通用事件总线。

## 依赖方向

```text
main.py → AstrBot 适配层 + PluginApplication
PluginApplication → 功能模块 + core
功能 service.py → 同目录 client.py + core
AstrBot 通知适配器 → core 的通知接口
core 不依赖 AstrBot 或任何具体功能
```

- **入口**只声明框架命令和转发生命周期，命令装饰器留在 Star 类中。
- **功能模块**拥有查询、参数解释、监控周期、通知文本和状态决策；查询返回字符串。
- **client.py**封装数据源请求、响应解析和展示格式。当前模块规模不大，暂不拆成大量小文件。
- **通知接口**定义发送成功为 `True`、无可用平台为 `False`、发送错误为异常。
  业务模块不知道 Context、平台管理器或 QQ 客户端；测试使用异步替身。
- **组合根**集中创建共享配置、存储与功能；功能之间不直接互相调用。

## 后台任务

`FeatureRuntime` 统一管理具有 `name`、`enabled`、`run()` 的后台功能：

- 名称唯一；重复初始化不会启动重复任务。
- 停止时取消并等待所有任务，单个任务异常不会阻止其他任务清理。
- 任务异常退出会记录日志；再次显式启动时可重建已结束的任务。
- 当前三个功能在自己的循环中处理请求异常与退避，运行时不额外实现重启策略。
- 关闭监控不关闭手动查询；配置由初始化时读取，修改后重载插件生效。

同步 HTTP 请求继续通过 `asyncio.to_thread` 执行，以保留既有数据源实现。
取消协程不会强制终止已执行的工作线程；请求依赖自身网络超时退出。
此处没有引入 HTTP 重试框架或线程池管理抽象。

## 状态与通知一致性

状态先写同目录临时文件、flush/fsync，再原子替换目标文件，避免半截 JSON。
读失败记录警告并返回独立的默认值；写失败抛出异常，由监控循环处理。

通知必须发送成功，才能持久化去重状态并更新内存快照。尤其是油价：未连接平台、
发送失败或写盘失败均不推进内存快照，后续检查仍能发现变化。
油价发送失败后按照原有每日调度重新检查，并非立即重试。

群消息与磁盘不是一个事务：发送成功后写盘失败可能导致再次推送，不保证严格恰好一次。
这是优先避免静默漏报的取舍。不同功能目前使用独立文件；不支持多进程同时写同一文件。

## 添加新功能

1. 新建 `plugin/features/<功能名>/`；将数据访问和格式化放入 `client.py`，查询与监控放入 `service.py`。
2. 在 `core/config.py` 的默认配置及根目录 `_conf_schema.json` 同步添加配置。默认配置是允许加载的字段集合。
3. 在 `PluginApplication` 中显式创建功能；有后台任务时将实例加入 `FeatureRuntime`。
   纯查询功能不需要继承 `MonitorFeature`，也不需要注册后台任务。
4. 在 `main.py` 添加对应 AstrBot 命令，通过 `query_result` 包装结果和异常回复。
5. 为查询、数据缺失、通知失败、状态提交及生命周期添加离线测试。

EVE 功能是纯查询模块，不加入 `FeatureRuntime`。它在 `plugin/features/eve/` 内部分为名称目录、
SDE 更新、ESI 行情/Redis 缓存和命令业务四个模块，通过 `PluginApplication` 显式装配。

扩展到另一类推送平台时优先替换或扩展 `adapters/astrbot/notifications.py`，
不要在每个功能中复制平台识别代码。架构解耦不代表已实现跨平台推送。

## 兼容性

- 插件标识 `yuxuandnf`、类名 `DNF_Plugin` 和三类基础命令保持不变。
- 原基础配置键、默认值和状态文件格式保持不变。
- 内部包名改为 `plugin`；不承诺旧内部 Python 导入路径兼容。
- 不再提供图片、音乐相关功能；未知历史配置字段被忽略，不自动修改外部配置文件。
- 油价非正数油耗/里程、畸形数字和多余参数现在返回参数提示；金币无有效均价时不推送零值。

## 验证范围

单元测试覆盖配置合并、配置 schema 一致性、状态迁移与原子写入、后台任务启停、
三个功能的查询和通知状态、AstrBot 入口命令集合和错误回复。
测试不验证外部行情网站的实时可用性，也不替代真实 AstrBot 平台上的发送和重载联调。
